\subsection{Query Locality: \textsc{simZipf} versus \textsc{simZipf+}}
\label{sec:simzipf}

Approximate caches are motivated by \emph{query locality}: successive
requests are not independent draws from the embedding space.
Locality, however, is not a single phenomenon, and conflating two
kinds of it produces an evaluation that is easy to win with a hash
table. We distinguish:

\begin{itemize}
  \item \textbf{Exact repetition.} The same embedding is issued more
        than once. A result-materialized cache answers it with an
        equality probe; reuse error is zero.
  \item \textbf{Similarity locality.} Distinct embeddings lie near
        one another because they encode related intents (reformulations,
        near-duplicate questions, session follow-ups). No request is
        bit-identical to a predecessor. Serving it requires a geometric
        hit predicate, not a hash.
\end{itemize}

In deployed vector search, the second kind is the common one.
Embeddings are functions of text, images, or context that almost never
repeat as identical floating-point vectors; what repeats is
\emph{topic}. A workload that manufactures exact repeats therefore
measures a cache's equality path, not the similarity path the system
was built to provide.

\paragraph{\textsc{simZipf} (Aker).}
Because public ANN query sets ship as unordered samples with no request
trace, Aker synthesizes a 100K stream that jointly models similarity
and skew~\cite{aker}. Construction has two stages.

\emph{Stage 1 (finite similar-query groups).}
Let $Q=\{q_1,\dots,q_{|Q|}\}$ be the unique queryset. For each base
query $q_i$ one builds a group $G_i$ of $G{=}50$ variants. On SPACEV,
which exposes only vectors, each variant is a linear interpolation
$q_i'=(1-\lambda)q_i+\lambda p$ with $p$ sampled from $Q$ and
$\lambda\sim\mathrm{Unif}(0,0.5)$. On TriviaQA, variants are
LLM-paraphrases of the source question, then re-encoded. The group is
materialized once and then frozen.

\emph{Stage 2 (Zipf over groups, uniform within a group).}
YCSB-C draws a Zipfian key sequence $k_1,\dots,k_N$ of length $N{=}10^5$
over the $|Q|$ groups (exponents $0.30$, $0.60$, $0.99$). The $t$-th
request uniformly samples one member of $G_{k_t}$ and emits that
already-stored vector.

The Zipf step concentrates accesses on a few groups. Because each
group contains only $50$ frozen vectors, a popular group is asked for
the \emph{same} members many times. Aker reports that equality hits
then dominate~\cite{aker}. Algorithmically:

\begin{quote}
\textsc{simZipf}: Zipf chooses a \emph{topic} (a group); the request is
a uniform draw from a \emph{closed} set of $50$ embeddings of that
topic. High skew $\Rightarrow$ the closed set is replayed
$\Rightarrow$ exact repeats.
\end{quote}

The interpolation in Stage~1 is real similarity locality; Stage~2
undoes it as soon as skew is high enough that $N/50$ exceeds the
number of hot groups. The $0.99$ setting is therefore closer to an
exact-repeat Zipf over a small vocabulary than to an open stream of
nearby queries. On SPACEV-1M that is exactly what we observe:
cumulative hit ratios at exponent $0.99$ are
$0.36$ (QVCache) versus $0.38$ (Aker), and most of Aker's hits are
\emph{exact} ($\approx 0.31$ of the last interval versus
$\approx 0.06$ approximate). A hash table is a sufficient cache for
the generator, so the two systems are not being asked to do different
work.

\paragraph{\textsc{simZipf+}.}
We keep Stage~2's Zipf over unique queries --- popularity of
\emph{topics} is a reasonable model of real traffic --- but we refuse
to close the variant set. Each access to topic $k_t$ synthesizes a
\emph{fresh} neighbor of $q_{k_t}$ that is not stored in a pool and is
not reused later:

\[
  q^{(t)} \;=\; (1-\varepsilon)\,q_{k_t} \;+\; \varepsilon\,p_t,
\]

where $p_t$ is a newly sampled vector from $Q$ (or a newly sampled
paraphrase, on text). We set $\varepsilon{=}0.01$, the same
interpolation weight as the windowed SIFT generator, so a revisit
stays in the topic's result neighborhood rather than walking toward a
random query. (Aker's Stage~1 weight $\lambda\sim\mathrm{Unif}(0,0.5)$
is a different, much larger perturbation; we do not use it here.)
Keys are drawn with YCSB-C scrambled Zipf over $|Q|$ (SPACEV-1M:
$|Q|{=}30{,}000$, $N{=}10^5$, exponent $0.99$, seed $42$). After
int8 quantization we reject accidental bit-identical collisions and
resample $p_t$, so the emitted stream has $N$ distinct vectors.
Algorithmically:

\begin{quote}
\textsc{simZipf+}: Zipf still chooses a \emph{topic}; the request is a
new embedding of that topic. High skew $\Rightarrow$ the same
neighborhood is visited often $\Rightarrow$ similar queries, never
(intended) exact repeats.
\end{quote}

\paragraph{Why QVCache wins on \textsc{simZipf+}.}
The two caches implement different hit predicates.

Aker is \emph{query-materialized}. An approximate hit requires the new
embedding to fall inside a previously cached \emph{query}'s ball
($\tau_q=\min(\textit{entry.thresh},\textit{minD})$, with TQ
initialized at $\textit{minD}/4$). A $1\%$ interpolation of the same
topic typically shares nearest neighbors in the \emph{data} space but
need not lie inside that ball in \emph{query} space, so the equality
path is empty and the filter path is conservative. On SPACEV-1M
\textsc{simZipf+} ($0.99$) Aker's exact-hit ratio is $0$ throughout;
hits are approximate only, and the cumulative hit ratio stays near
$0.30$.

QVCache is \emph{data-materialized}. A miss inserts the retrieved
neighbors into mini-indexes; a later query hits if a regional PCA
threshold $\theta$ says those cached \emph{objects} still explain the
new vector. Revisits of a Zipf-hot topic therefore reuse the same
result neighborhood even though no two query vectors are equal. On
the same stream the cumulative hit ratio is $0.73$ (late-stream
intervals $\approx 0.8$--$0.9$), with cache-hit recall
$\approx 0.87$---comparable to Aker's when it does hit, so the extra
hits are not cheap false positives.

The gap is the evaluation we actually want: both systems see the same
skewed topics, the same capacity budget (QVCache
\texttt{MEMORY\_INDEX\_MAX\_POINTS}${}=200$k versus Aker pool
$320$k), and no manufactured equality. QVCache's advantage is that
similarity of \emph{intent} is similarity of \emph{neighbors}, not
proximity of query vectors under a tight query-space $\tau$.

The same split appears on windowed SIFT (fresh $\varepsilon{=}0.01$
copies, no Zipf): QVCache repeat-pass hit ratio $\approx 0.88$--$0.90$
versus Aker $\approx 0.32$--$0.47$ with exact hits $\approx 0$.
\textsc{simZipf+} shows that this is not an artifact of sliding
windows. Windowing is \emph{temporal} (bursty sessions);
\textsc{simZipf+} is \emph{Zipfian} (skewed topic popularity over a
long stream). Both belong to similarity locality; neither belongs to
exact repetition.

\paragraph{What each workload is allowed to claim.}
\begin{itemize}
  \item \textsc{simZipf} (Aker) is the right comparison when the
        question is ``does the system match Aker's published
        numbers?'', including the equality-hit share they report.
  \item \textsc{simZipf+} is the right comparison when the question is
        ``does similarity caching help when the same \emph{intent}
        recurs as a new vector?'' --- the realistic query process.
  \item Reporting only \textsc{simZipf} at exponent $0.99$ overstates
        the value of hash aliases and hit-type adaptation, because both
        are fed by exact repeats that the generator put there.
\end{itemize}
